# ACC v0.2 Communication-First Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship ACC v0.2 as a local-first communication layer in which independently opened AI sessions discover peers, exchange threaded messages, reply, acknowledge, and use only delivery capabilities proven against real clients.

**Architecture:** Core records vendor-neutral conversations and truthful per-recipient receipts before any transport is attempted. A separate delivery-router package selects one generation-bound recipient binding and delegates an offer to a certified adapter; hooks and native client subprocesses commit `offered` only after bytes cross their transport boundary. Orchestration nouns and execution capabilities are removed rather than migrated.

**Tech Stack:** Node.js 24+, ESM, `node:test`, npm workspaces, Node built-ins only, filesystem transactions, JSON-RPC over stdio or a local Unix socket.

**Spec:** `docs/superpowers/specs/2026-09-01-acc-v0.2-communication-first-design.md`

## Global Constraints

- Node.js is `>=24`; production runtime dependencies remain exactly zero outside this workspace's bundled packages.
- Core never imports an adapter, Git, `node:child_process`, or vendor vocabulary.
- Vendor-specific behavior remains under `packages/adapter-*`.
- ACC never launches, resumes, terminates, supervises, or owns a target AI session.
- Messages from peers are attributed untrusted data; raw transcripts are never read or persisted.
- Nothing ACC writes may land inside a repository.
- Hooks remain fail-open and bounded.
- `queued`, `offered`, `retrieved`, and `acknowledged` describe different observable facts; `seen` and terminal delivery `failed` do not exist.
- A `true` native capability requires a real-client fixture and matching exact client-version evidence; an unknown version degrades.
- v0.2 rejects v0.1 records. No compatibility reader, archive command, data conversion, or automatic deletion is implemented.
- Production modules and focused tests stay below 300 lines unless a cohesion header explains the exception.
- Every new or corrected gate is proved by mutating the behavior it claims to protect and observing the test fail.
- Every task ends with a focused commit; do not push or merge unless the maintainer asks.

## File Structure

The implementation converges on these responsibilities:

- `packages/protocol/src/conversations.mjs` — message kinds, obligations, kind/obligation/addressing validation, and structured handoff validation.
- `packages/protocol/src/schema.mjs` — v0.2 record and closed event schemas only.
- `packages/protocol/src/states.mjs` — receipt transition machine only.
- `packages/core/src/conversations.mjs` — idempotent message recording, thread rules, room audience resolution, and finish transaction.
- `packages/core/src/receipts.mjs` — offer attempts, retrieval, acknowledgement, and receipt ownership.
- `packages/core/src/inbox.mjs` — recipient reads and atomic replies.
- `packages/core/src/attention.mjs` — the six explicit v0.2 attention rules.
- `packages/core/src/delivery-bindings.mjs` — generation-bound ephemeral binding publication and lookup.
- `packages/delivery-router/src/router.mjs` — recipient policy, eligibility, adapter selection, and offer-then-commit orchestration without session ownership.
- `packages/adapter-sdk/src/certification.mjs` — evidence shape and version-specific effective capability resolution.
- `packages/adapter-sdk/src/context-projector.mjs` — untrusted next-turn messages and post-live breadcrumbs.
- `packages/adapter-claude-code/src/channel.mjs` — Claude Channel JSON-RPC subprocess and reply/ack tools.
- `packages/adapter-codex/src/app-server-client.mjs` — bounded client for an already-running Codex app-server endpoint.
- `packages/adapter-*/certification.json` — machine-readable capability claims tied to captured fixtures.
- `scripts/spikes/` — explicit real-client capture tools; never imported by production packages.

- [ ] **Step 3: Implement the bounded JSON-RPC peer and closed capture validator**

```js
export function validateCapture(value) {
  const required = ["client", "version", "platform", "observedAt", "capability",
    "result", "fixture", "idle", "busy", "reply", "duplicate", "fallback",
    "limitations"];
  for (const key of required) {
    if (!Object.hasOwn(value, key)) throw new Error(`capture requires ${key}`);
  }
  if (!new Set(["pass", "fail"]).has(value.result)) {
    throw new Error("capture result is pass or fail");
  }
  return Object.freeze({ ...value });
}
```

The peer must use newline-delimited JSON, monotonically increasing request ids, a per-request timeout, stderr capture capped at 16 KiB, and `SIGTERM` only for the proxy child it started.
