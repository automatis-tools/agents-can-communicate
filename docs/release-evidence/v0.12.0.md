# ACC v0.12.0 release candidate evidence

This candidate ships the work merged to main after 0.11.1:

- a notice for messages left for a session that ended (#324, issue #320);
- refusal to renew a lapsed claim (#319, issue #295);
- Antigravity desktop TCP discovery without blocking filesystem calls on macOS (#318);
- the linked ACC mark in the README and the Codex plugin (#326);
- the Awesome Claude Code badge (#321, issue #289).

#322 and #327 (issue #323) change tests and scripts only; they change no packed file. The new attention kind is why this release is a minor version. Store contract 7 and managed-update protocol 2 are unchanged. This is candidate preparation, not publication.

## Upgrade from published 0.11.1

The previous archive was downloaded from npm. Its SHA-256 matched the published 0.11.1
record: `a4f76437f39c15f48585949b0d4e8d4fc8f968ed3b8e6ae57e521d9d81191af3`.

Setup:
- The archive was installed with isolated home, data, project and npm cache directories.
- Claude Code 2.1.259 and Codex 0.135.0 detection shims stood in for the clients.
- Both integrations were installed, and automatic updates were turned off.
- `acc update --yes` received the exact 0.12.0 archive from a local registry. Eleven checks passed.

- The updater activated 0.12.0. It downloaded the archive from the local registry, and the registry logged the request for the archive.
- The automatic-update opt-out set before the update survived it (`auto: false`).
- An MCP participant on the old 0.11.1 process held a question sent before the update.
  After the switch, that old process read the question with the same id and subject and
  answered it. The reply reached the sender.
- `.claude/settings.json` and `.codex/config.toml` kept their bytes.
- All 378 archive files were installed in the active generation with the same SHA-256.
- After the original npm installation was removed, the stable CLI reported 0.12.0. The
  stable read-only indicator answered (`ACC ! · acc doctor`).
- The local registry, MCP process and fixture directories were closed and removed.

The detection shims avoid native service preparation, so this proves package and state
continuity, not native activation.

## Limits

- No new live capability, captured minimum or store contract is declared.
- Published source, artifact and native capture records remain unchanged.
- These checks do not establish native activation of the maintainer's running sessions, or native behavior on Windows and Linux. CI covers both platforms' suites.
- Publication remains a separate step after the release pull request merges.
