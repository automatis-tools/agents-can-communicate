# ACC v0.15.1 release candidate evidence

This candidate ships the work merged to main after 0.15.0: #423, which moves ACC's Codex hooks
into a plugin of their own so that an ACC update no longer makes Codex ask to trust them again,
and makes the update manager's lock compare the full file id on Windows.

The release keeps store contract 8 and managed-update protocol 2, so it is a patch version with
no data migration. This is candidate preparation, not publication.

## Exact artifact

- Source: clean commit `e10de78870089cd81450762e191c3f3b492c4718`, on main `ce17a805` (PR #423).
- Archive: `agents-can-communicate-0.15.1.tgz`, 659,296 bytes, 392 files.
- SHA-256: `860c533671061909a8f48a094a055a5f0b297ffe16957531899252373d8104d2`.
- SHA-1: `d71b6332da93c1bb57d0816a670bb764020bc09f`.
- Node 24.4.0, npm 11.4.2, macOS arm64.
- The root manifest, fifteen workspaces and two versioned embedded manifests declare 0.15.1. So
  does the lockfile. The two Codex plugin manifests carry no version in source; ACC stamps them
  at install.
- `npm ci` with a release-only cache and the syntax check of 923 modules passed before commit A.
- The documentation-reader audit pin was refreshed in commit A. The tests and the test helpers
  changed since 0.15.0 name no documentation. The external reader list is unchanged.

The exact archive passed `scripts/verify-package.mjs`, which checks:
- bundled workspaces, the certification inventory and packed links;
- all four binaries, doctor and a non-Git workspace;
- client-home restoration after install and uninstall.

Source packed from commit A passed all 25 managed-update checks in
`tests/acceptance/managed-*-packed.test.mjs`.

## Upgrade from published 0.15.0

The previous archive was downloaded from npm. Its SHA-256 matched the published 0.15.0 record:
`0364857eab90a1edd8aa2b63b1f384f01265e12864d3a7db3f786d254524d903`.

Setup:
- isolated home, data home, npm prefix and npm cache;
- real client executables on `PATH` through a symlink-only directory: Claude Code 2.1.322 and
  Codex 0.167.2;
- a local registry that served the exact candidate as 0.15.1, and then the same archive
  re-versioned as 0.15.2.

Under 0.15.0, Claude Code was installed with no `--delivery` and Codex with `--delivery off`.
Twenty-three checks passed:
- 0.15.0 installed both integrations; its single Codex plugin held the hooks.
- `acc update --yes` activated 0.15.1, and the control file kept automatic updates off.
- After the update, Codex's cache held:
  - the skill plugin at 0.15.1 with no hooks, beside the previous copy;
  - the hooks plugin `agents-can-communicate-hooks` at 0.15.1 with `hooks.json`.
- ACC's block in `config.toml` enables the hooks plugin, and the marketplace lists both plugins.
- Claude Code's `settings.json` kept its bytes.
- A question recorded under 0.15.0 crossed the update. The peer saw it and replied, the sender
  received the reply, and the store stayed on contract 8.
- All 392 archive files were installed in the active generation with the same SHA-256.
- Doctor ran on 0.15.1.
- The update to 0.15.2, whose hook files are the same, left the hooks plugin's 0.15.1 copy in
  place with the same content hash (`sha256:feb0667d…`, by a port of Codex's
  `plugin_fingerprint.rs`). The marketplace copy still names 0.15.1. The skill plugin moved
  to 0.15.2.
- The stable CLI answered 0.15.2 after the npm installation was removed.

No Codex session was opened in this run, so it proves the files Codex trusts, not the trust
dialog itself.

## Real clients

The real-terminal runs are recorded in
[development evidence](codex-hooks-own-plugin-2026-11-11.md), on Codex CLI 0.167.1:
- A fresh install asked once to review the five hooks of `agents-can-communicate-hooks`.
- An update that left the hooks alone asked nothing, and a session open across it kept
  running them.
- From published 0.15.0 the update asked once more.

Commit A differs from the source of those archives by the lock change in
`packages/cli/src/managed-runtime/mutex.mjs`, by version numbers, by the `docs/UPGRADING.md`
section and by the documentation-reader pin.

## Full suite

With commit B's evidence in place, the full suite ran 4149 tests under Node 24.4.0 at load average
18–19. Of those, 4138 passed, 11 were skipped and none failed.

## Limits

- Codex 0.167.2 ran in the upgrade check without a session. The trust dialog was observed on
  0.167.1 only.
- The Windows lock fix is covered by a test that models NTFS file ids on every platform and by
  the Windows CI run. It was not reproduced on a Windows machine.
- Linux and Windows Codex were not run.
- Publication remains a separate step after the release pull request merges.
