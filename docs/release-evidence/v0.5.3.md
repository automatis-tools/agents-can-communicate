## Behavior and compatibility limits

Unanswered questions and requests now require `reply`, not bare `ack`. An answer,
clarification, or refusal satisfies that communication obligation. Historical
acknowledged receipts remain valid. No state migration is required.

An acknowledgement still does not establish accepted scope or executed work.
`finish` still closes the sender's ACC presence without waiting for acceptance.
The five skill templates distinguish authorized continuation, missing scope,
and explicit context-only transfer.

Client executables in the upgrade preflight only reported fixture versions.
They did not execute models or establish native delivery. No new live handoff,
already-loaded skill refresh, or active-client update was captured for this archive.
Existing certification files ship unchanged and retain their original provenance.
The prior synthetic skill exercise and its limits remain in
[the handoff validation record](../internal/evidence/handoff-acceptance/validation.md).

## CI follow-up

The first CI run for [PR #126](https://github.com/automatis-tools/agents-can-communicate/pull/126)
failed one Ubuntu/Node 24 test: `a background poll releases the update lock while
waiting for clients`. Its foreground admission timed out after 500 ms. The other
five PR checks passed. The failed job is retained at
[Ubuntu CI](https://github.com/automatis-tools/agents-can-communicate/actions/runs/34718852546/job/103620850726).

The old test's `ready` marker was written during preparation, before the remaining
activation work and durable writes under the worker lock. An isolated diagnostic
held the fixture's admission lock after that marker and reproduced the same timeout.
Releasing that deliberate delay let the unchanged worker enter its 60-second idle
interval and admit a foreground operation. This proves a premature synchronization
boundary; it does not measure which operation consumed the CI runner's time.

Commit `cbf0aa189dd57cc81226cd3d0ae93c2716d37afa` changes only the test. The child now
signals when its real idle timer starts. The test preserves the timer, real locks,
500 ms admission check, and duplicate-worker check. Startup and early exit have
bounded, explicit failure paths.

Mutation proof: moving the idle sleep inside the worker-lock callback made the
corrected test fail with `manager lock held; acquisition timeout`. Restoring the
original worker made all six focused tests pass. Twenty more targeted runs passed
at concurrency four. Independent review found no issues and passed all six tests
on Node 24.4.0 and 26.5.1. Syntax checks passed for all 520 tracked modules.
