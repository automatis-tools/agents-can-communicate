# ACC v0.15.0 release candidate evidence

This candidate ships the work merged to main after 0.14.1: #421, which turns live delivery on by
default, reports a sender refused by Antigravity's relay as `transport_permission_denied`, and
limits the install's delivery note to clients that installed.

The default changes for existing installs, so this is a minor version. The release keeps store
contract 8 and managed-update protocol 2 and adds no data migration. This is candidate
preparation, not publication.

## Exact artifact

- Source: clean commit `a8c492509457741787d5afe0b8bd42dd3154d99b`, on main `fdbce576` (PR #421).
- Archive: `agents-can-communicate-0.15.0.tgz`, 656,464 bytes, 390 files.
- SHA-256: `0364857eab90a1edd8aa2b63b1f384f01265e12864d3a7db3f786d254524d903`.
- SHA-1: `11b51fabc9182be7b5f654e30f186719a4988a62`.
- Node 24.4.0, npm 11.4.2, macOS arm64.
- The root manifest, fifteen workspaces and two versioned embedded manifests declare 0.15.0. So
  does the lockfile.
- `npm ci` with a release-only cache and the syntax check of 921 modules passed before commit A.
- The documentation-reader audit pin was refreshed in commit A. Of the tests and helpers changed
  since 0.14.1, only `tests/docs/commands.test.mjs` and `tests/docs/executable.test.mjs` read
  documentation, and their change only narrows `PATH`. The external reader list is unchanged.

The exact archive passed `scripts/verify-package.mjs`, which checks:
- bundled workspaces, the certification inventory and packed links;
- all four binaries, doctor and a non-Git workspace;
- client-home restoration after install and uninstall.

Source packed from commit A passed all 25 managed-update checks in
`tests/acceptance/managed-*-packed.test.mjs`.

## Upgrade from published 0.14.1

The previous archive was downloaded from npm. Its SHA-256 matched the published 0.14.1 record:
`d1c569b79df46e12ff86e586f275d11908b6d64c8335c5872358a3e70138d7c9`.

Setup:
- isolated home, data home, npm prefix and npm cache under a resolved path;
- real client executables on `PATH` through a symlink-only directory: Claude Code 2.1.321,
  Codex 0.167.0, Antigravity 1.5.3 and Kimi Code 2.5.2, so that the native probes ran;
- a local registry that served the exact candidate as 0.15.0.

Two arrangements ran, with 24 and 22 checks. All passed.

| Installed under 0.14.1 with no `--delivery` | Installed with `--delivery off` |
|---|---|
| Claude Code, Antigravity, Kimi | Codex |
| Codex, Kimi | Claude Code |

In both arrangements:
- `acc update --yes` activated 0.15.0 and the control file kept automatic updates off.
- Every client that ACC had left off became `actionable` with a `default-enabled` decision.
- The client turned off with `--delivery off` kept its `explicit-option` off, and its
  configuration file kept its bytes.
- A question recorded under 0.14.1 crossed the update. The peer saw it and replied, the sender
  received the reply, and the store stayed on contract 8.
- All 390 archive files were installed in the active generation with the same SHA-256.
- Doctor ran on 0.15.0, and the stable CLI answered 0.15.0 after the npm installation was removed.

In the arrangement with Codex and Kimi turned on, the Codex profile written in the same update
carries the `127.0.0.1` rule.

## Fresh install

The exact archive was installed in another isolated home, with the real Claude Code, Antigravity
and Kimi Code executables. Plain `acc install` recorded `actionable` and `default-enabled` for all
three, asked nothing, and printed the delivery note naming the three clients. Codex was left out
of this run so that no vendor service would start.

## Real clients

The real-terminal runs are recorded in
[development evidence](delivery-on-by-default-2026-11-09.md): five three-window deploy-lane runs
on `f826841a`, and on `7d749c7a` one more run and a Codex request that woke an idle Antigravity
session after an approved retry. Commit A differs from the source of those archives by commit
`66ec99a7` (the install's delivery note), by version numbers, by the `docs/UPGRADING.md` section
and by the documentation-reader pin.

## Full suite

With commit B's evidence in place, the full suite ran 4143 tests under Node 24.4.0 at load average
24–72. Of those, 4133 passed, 10 were skipped and none failed.

## Limits

- Real terminal sessions did not run on the exact archive. The upgrade and fresh-install runs
  above used real client executables for detection and probes, with no session open.
- Kimi Code's live delivery after this update was recorded and not observed waking a session.
  The Claude Code bypass-permissions wake was not part of these runs.
- Every Codex send to Claude Code or Antigravity starts inside the sandbox, so a live wake costs
  a refused attempt and an approved retry.
- Windows and Linux ran the automated suite only.
- Publication remains a separate step after the release pull request merges.
