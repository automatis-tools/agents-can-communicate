# ACC v0.8.0 release evidence

Claude Code live delivery now wakes a session through the inbox socket that Claude Code opens for
every session. You start Claude Code with your ordinary command: the `claude` shim, the
development-channel flag and the Channel MCP server are gone. A sender is told what happened to
each message, in words that match what the recipient's client did.

`extensions`, which 0.7.x skips, and the new delivery codes are returned, never stored.

managed runtime (it reported `version 0.7.1`), and the installed 0.8.0, against one store:

## Compatibility notes

- `ACC_NATIVE_DELIVERY_POLICY`, `ACC_BYPASS` and `ACC_BOOTSTRAP_DEBUG` are gone; live-delivery
  consent comes only from the install record.
- `recipient_unavailable` now means an open session whose live transport could not be reached.
  An online recipient with no live transport is `no_live_transport`; a recipient with no open
  session is `recipient_offline`, with `endReason` when the client gave one.
- A wake held for approval carries `"pendingApproval": true`.
- The normalised hook event carries `permissionMode` and `endReason`, `null` unless the client
  reports them.
- A 0.7.x updater accepts this package: `bin/entrypoints/acc-bootstrap.mjs` and
  `bin/entrypoints/acc-claude-channel.mjs` remain as stubs.

## Limits

- Claude Code live delivery is certified on darwin-arm64 from 2.1.282 and was exercised on
  2.1.283. `darwin-x64`, Linux and native Windows are uncaptured; there a Claude Code session
  keeps next-turn delivery.
- Claude Code's `mcp_toggle` leaves a disabled MCP server running until Claude Code exits; the
  retired Channel stub is one such server. That is the client's behaviour for every MCP server.
- Whether a model answers a peer's question is its own judgement: in one real run a session saw
  an unrelated peer question on its next turn and asked its user first.
- 0.7.x set `~/.zshrc` to mode 0600 when it added its PATH block and recorded nothing to undo that
  with; retiring the block keeps the mode the file has.
- Unicode line separators inside one-line header fields are tracked in #200.
