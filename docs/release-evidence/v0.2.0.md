## Packed cross-vendor result

The acceptance creates a tarball, installs it offline into an empty consumer, and invokes
the installed JS bin targets with `process.execPath`. Product imports used to publish the
synthetic version-bound delivery binding resolve only inside the installed bundle; no
workspace source or workspace symlink is imported.

The packed run proves:

- Claude question → Codex inbox → Codex answer on the same thread → Claude acknowledgement;
- Codex question → Claude inbox → Claude answer on the same thread → Codex acknowledgement;
- each root has `threadId === messageId`; each answer retains that thread and names the root
  in `inReplyTo`;
- recipient receipts move from `queued` to `retrieved` to `acknowledged`;
- the human never copies the peer message body, and idempotency keys return the same ids;
- both participant generations restart, old generations and stale bindings are rejected;
- a synthetic `99.0.0` client version reports `unsupported_client_version`, withholds the
  body from hook output, and remains recoverable from `acc inbox`;
- installed MCP answers `acc_status`;
- install followed by two uninstalls preserves all foreign Claude/Codex config bytes; and
- the project directory remains empty.

The retained 0.152.0/2.1.252 native captures are failures, so those versions visibly use
the inbox fallback in this run. Separately certified exact older versions may use
next-turn delivery; unknown and uncertified versions are never promoted to it.

## Gate and mutation evidence

The initial sandbox-only baseline produced eight Unix-socket `EPERM` failures plus the
expected old recorded-candidate failure. Those were not relabelled as product skips.

The first escalated default-concurrency run exposed release-runner contention: Node used
the host's 18-file default while packaging tests spawned npm/tar/Node children. One of four
fresh-workspace agents missed the writer deadline after 3.989 seconds, and four Claude
channel connects observed the socket file before its listener accepted connections. The
store-concurrency test passed alone in 0.958 seconds. The channel test passed alone, then
was hardened to retry only `ECONNREFUSED`/`ENOENT` at the connect boundary. Top-level test
file concurrency is now four; the actual four-process race remains unchanged.

With bounded concurrency, the complete escalated pre-evidence run finished in 88.929
seconds: 1,171 passed, one expected old-provenance failure, and one existing environment
skip. The four-agent test passed in 1.449 seconds and all seven Unix-socket channel tests
passed. The final post-evidence gate finished in 92.673 seconds: 1,172 passed, zero failed,
and one existing environment skip: `uninstall is planned from the record, not only from
the machine` skipped because Gemini CLI is installed on this machine, so the test could
not exercise the client-disappeared branch.

Required mutations were observed before restoration:

1. Removing only `@agents-can-communicate/delivery-router` from `bundleDependencies`
   failed the packed gate with `the installed acc command cannot compose delivery without
   the router`; offline clean installs also failed.
2. Changing packed core replies from `answer` to `note` failed cross-vendor acceptance with
   `'note' !== 'answer'`.
3. Before the public-doc allowlist, the tarball-link gate named nine missing local targets.

After each restoration, focused packed tests and `verify-package` passed.

## Limitations

- Native mid-turn/live-push delivery is not certified for Codex 0.152.0 or Claude Code
  2.1.252; durable inbox recovery is the supported fallback.
- The currently installed Claude 2.1.258 has no retained capability capture and is treated
  as uncertified.
- Windows is unsupported in v0.2.0. The synthetic POSIX client-version cross-vendor test
  explicitly skips there; it is not counted as a passing Windows native capture.
- This evidence was produced on macOS arm64. No Linux CI run was performed in this task.
- No release publication action was performed.
