## Packed cross-vendor result

The acceptance creates a tarball, installs it offline into an empty consumer, and invokes
the installed JS bin targets with `process.execPath`. Product imports used to publish the
synthetic version-bound delivery binding resolve only inside the installed bundle; no
workspace source or workspace symlink is imported.

The packed run proves:

- Claude question → Codex inbox → Codex answer on the same thread → Claude acknowledgement;
- Codex question → Claude inbox → Claude answer on the same thread → Codex acknowledgement;
- each root has `threadId === messageId`; each answer retains that thread and names the root
  in `inReplyTo`;
- recipient receipts move from `queued` to `retrieved` to `acknowledged`;
- an installed-CLI command trace shows each peer body only in its originating `message` or
  `reply` arguments, never copied into a responder command; idempotency retries keep the ids;
- both participant generations restart, old generations and stale bindings are rejected;
- a synthetic `99.0.0` client version reports `unsupported_client_version`, withholds the
  body from hook output, and remains recoverable from `acc inbox`;
- installed MCP answers `acc_status`;
- install applies all five detected adapters, stamps installed manifests at 0.2.0, and the
  first uninstall restores all foreign Claude/Codex/Kimi topology, modes, and bytes while
  the second reports no removals or changes; and
- the project directory remains empty.

The retained 0.152.0/2.1.252 native captures are failures, so those versions visibly use
the inbox fallback in this run. Separately certified exact older versions may use
next-turn delivery; unknown and uncertified versions are never promoted to it.

## Gate and mutation evidence

The initial sandbox-only baseline produced eight Unix-socket `EPERM` failures plus the
expected old recorded-candidate failure. Those were not relabelled as product skips.

The first escalated default-concurrency run exposed release-runner contention: Node used
the host's 18-file default while packaging tests spawned npm/tar/Node children. One of four
fresh-workspace agents missed the writer deadline after 3.989 seconds, and four Claude
channel connects observed the socket file before its listener accepted connections. The
store-concurrency test passed alone in 0.958 seconds. The channel test passed alone, then
was hardened to retry only `ECONNREFUSED`/`ENOENT` at the connect boundary. Top-level test
file concurrency is now four; the actual four-process race remains unchanged.

After the tight-budget fallback review fix, the clean-A6 pre-evidence run finished in 104.697
seconds: 1,194 passed, one expected old-provenance failure, and one existing environment
skip out of 1,196 tests. The expected failure named only the hook-runner source/test files
changed since A5. The focused hook/process set passed 34/34, and `npm run check`
syntax-checked 265 files. The skip is `uninstall is planned from the record, not only from
the machine`: Gemini CLI is installed here, so that test cannot exercise the
client-disappeared branch.

Required mutations were observed before restoration:

1. Removing only `@agents-can-communicate/delivery-router` from `bundleDependencies`
   failed the packed gate with `the installed acc command cannot compose delivery without
   the router`; offline clean installs also failed.
2. Changing packed core replies from `answer` to `note` failed cross-vendor acceptance with
   `'note' !== 'answer'`.
3. Before the public-doc allowlist, the tarball-link gate named nine missing local targets.
4. Staling the Gemini extension manifest to 0.1.6 failed the embedded artifact gate; with
   installation stamping removed, the installed-manifest gate independently reported
   0.1.6 instead of the adapter package's 0.2.0.
5. Teaching `queued -> injected -> seen` in shipped `DESIGN_DECISIONS.md` failed the public
   documentation semantic gate. Removing packaged `AGENTS.md` also made the tarball link
   gate name the remaining relative `docs/index.md -> AGENTS.md` link until it was made an
   absolute repository link.
6. Suppressing recorded ancestor cleanup left ACC-created empty client directories behind
   and failed the focused ownership test. The installed-artifact flow now snapshots every
   directory, regular file, and symlink with mode, bytes, or target as applicable.
7. Removing the isolated npm cache prefix from the documented verifier command failed its
   executable documentation gate.
8. Bypassing connect-failure cleanup left the spawned channel's temporary directory behind
   and failed deterministically. Readiness failure also kills and awaits the child before
   removing its temporary directory; successful close is idempotent.
9. The shipped Codex plugin's `UNLICENSED` value failed the tarball metadata gate before it
   was corrected to MIT.
10. Replacing the atomic candidate-directory rename with the former `mkdir` grant made the
    ownerless-lock regression fail with `ran: false`, exit code 5, and the orphaned
    `writer.lock` still present. Restoring A4 made the exact selected test pass and leave

11. Before adding the compact degradation path, the platform-independent 200-byte
    regression failed with only the ambient peer-presence line: the exact
    `acc inbox --message message_…` command was absent. Restoring A5 kept the peer body out,
    left its receipt queued, stayed within 200 bytes, and exposed the exact recovery command.
12. With two queued messages and an 84-byte budget, A5 still spent space on the optional

    first-message recovery command fit. The strengthened regression failed on that output;
    A6 drops the optional count first, stays within 84 bytes, withholds both bodies, and
    leaves the receipt queued.

After each restoration, focused packed tests and `verify-package` passed.

## Limitations

- Native mid-turn/live-push delivery is not certified for Codex 0.152.0 or Claude Code
  2.1.252; durable inbox recovery is the supported fallback.
- The currently installed Claude 2.1.258 has no retained capability capture and is treated
  as uncertified.
- Windows is unsupported in v0.2.0. The synthetic POSIX client-version cross-vendor test
  explicitly skips there; it is not counted as a passing Windows native capture.
- This candidate evidence was produced on macOS arm64. The first Linux CI run found the
  uncertified-platform tight-budget defect; the A5 CI rerun passed on Ubuntu Node 24, and
  the narrower A6 review-fix rerun is pending.
- No release publication action was performed.
