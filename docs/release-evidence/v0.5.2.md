# ACC 0.5.2 candidate evidence

This candidate is prepared for review. It has not been tagged or published.
It removes two costs an agent pays on every peer exchange, both of them in what
the skill says rather than in what the CLI does.

## What the measurement started from

A live Codex session was asked, through ACC, to read its own `acc doctor` and
report one line back. It did so, and the transcript showed two calls that could
not have been needed.

| Call | Why it happened | Cost |
|---|---|---|
| `doctor` with `--session`/`--generation` | the skill scoped the rule to "the CLI examples below" | one failed call |
| `inbox --message` on a message already delivered whole | "fetch before acting" read as a rule | ~84 tokens |

Neither is a CLI defect. Every command that acts as a participant takes the
pair, and every command that acts on the installation refuses it; that split
matches the grouping the CLI's own help prints. The strictness that produced the
refusal is deliberate and load-bearing elsewhere: a message body legitimately
begins `--- a/file`, and the parser distinguishes that from a typo by checking
whether the token names a real option of the command.

## What changed

**The credential rule is stated through what the arguments mean.** They name the
participant that is calling, so a command acting on the installation rather than
as a participant refuses them, and that refusal says nothing about the
credentials. No machine-level command is named: a skill that taught those would
have models running the installer, which `tests/docs/skills.test.mjs` guards
against on purpose.

**The fetch rule and its exception now sit together.** A header carries no body,
so fetch the one you chose; a message that reached you with its body attached is
complete, and fetching it again buys nothing. Previously the second half sat
eight lines lower and read as an aside.

**Each adapter installs one shim and the examples name it.** The examples used to
carry the whole invocation — a data home, an interpreter and a script.

| Client | Before | After | Saved across 23 examples |
|---|---|---|---|
| Codex | 186 bytes | 78 | ~690 tokens |
| Claude Code | 125 bytes | 84 | ~262 tokens |

## What was deliberately not done

**The parser was not loosened.** Accepting the pair on a machine-level command
and ignoring it would remove the failure, but `doctor` prints per-session lines,
so a silently ignored `--session` could read as scoping that never happens.

**The repeated paths were not simply shortened in place.** They are absolute
because a skill that said `acc` once produced a worse failure than a missing
command: a Claude Code session that could not find it read the store's JSON,
worked out the schema, and wrote records and events by hand, inventing an event
type, a harness name and its own generation tokens. The shim keeps that
guarantee — it resolves nothing through PATH — and only moves it one level down.

**The shim is per adapter, not per machine.** One client pins a data home because
its sandbox scrubs the environment; another deliberately leaves it unset so an
operator's own `ACC_DATA_HOME` still wins. A single shared shim could not honour
both.

**The shim fails loudly where the hook shim fails open.** A hook that cannot run
must not stop somebody's session. This runs because an agent asked to
coordinate, and an agent told nothing went wrong is exactly the case that
produced hand-written records.

## Tests

`tests/process/skill-command.test.mjs` no longer looks for a path in the skill's
text; it takes the path the skill names and runs it, so what an agent copies is
what the test executes. `tests/acceptance/managed-install-packed.test.mjs`
follows the same indirection: the skill names a shim, and that shim must name the
managed runtime's own CLI rather than another install. Six new cases in
`packages/adapter-sdk/test/hook-shim.test.mjs` walk the whole fallback ladder and
assert the non-zero exit. `tests/docs/skills.test.mjs` gained a case that fails
against the old wording — verified by reverting one skill and watching it fail.

Four tree-content assertions were updated to expect the new file. They failed
first, which is what they are for.

## Limits

The saving is per skill load, once per session per agent, and is concentrated on
Codex: its examples carried a pinned data home that Claude Code's do not.

Two tests in this suite fail under load on a slow runner and pass on re-run:
the reclamation race in `packages/storage-filesystem/test/lock-changing-hands.test.mjs`,
whose proof-of-exercise assertion needs a clean read to land between flips, and
`packages/hook-runner/test/native-attempt-doctor.test.mjs`. Neither is a product
defect, and neither is fixed here.

The limits recorded for 0.5.0 still apply. The first update after that release
waits for every live process to exit, a `STORE_VERSION` change still requires
every live process to exit, and native delivery binds at a session's first turn.
