# ACC v0.12.2 release candidate evidence

This candidate ships the work merged to main after 0.12.1: a process that may not use ACC's
state is told so, instead of being told an update is unfinished (#334, issue #316).

The change adds no attention kind, CLI command or captured minimum, so this release is a patch. The launcher's closed module set gains `admission.mjs`. Store contract 7 and managed-update protocol 2 are unchanged: between `v0.12.1` and this candidate, the protocol, core and storage packages change only their version field. This is candidate preparation, not publication.

### State continuity, with client detection shims

Eleven checks passed:
- The updater activated 0.12.2 from a local registry that served the exact archive.
- The automatic-update opt-out set before the update survived it.
- An MCP participant on the old 0.12.1 process held a question across the switch. It read the question afterwards and answered it, and the reply reached the sender.
- `.claude/settings.json` and `.codex/config.toml` kept their bytes.
- All 380 archive files were installed in the active generation with the same SHA-256.
- The stable CLI reported 0.12.2 after the original npm installation was removed. The stable read-only indicator answered.

### The new launcher module

Eight checks passed:
- The 0.12.1 updater activated 0.12.2 and wrote a second launcher set.
- That set carries `admission.mjs`, and the stable `acc` and `acc-hook` launchers import it.
- Unsandboxed, the stable hook ran without a module error.
- Under `sandbox-exec`, with writes denied below the data home:
  - the stable CLI answered `status` with `reasonCode: state_access_denied` and `cannot write ACC's state: fchmod …`;
  - the stable hook exited 0 with `cannot write ACC's state (EPERM); session may continue`.

The detection shims avoid native service preparation, so these checks prove package and
state continuity, not native activation.

## Full suite

With commit B's evidence in place, the full suite ran 3491 tests at load average 5–13: 3482
passed, 9 were skipped, none failed. It included the packed hook and managed-update checks, and
the denied-state tests added in #334.

## Limits

- No new live capability, captured minimum or store contract is declared.
- ChatGPT Work Mode was not driven. Whether ACC has a supported execution path there stays open in #316.
- The end-to-end denial checks use `sandbox-exec` and `chflags uchg`, which are macOS's. CI runs the unit tests on Linux and Windows.
- Publication remains a separate step after the release pull request merges.
