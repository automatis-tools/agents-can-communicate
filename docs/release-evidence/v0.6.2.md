Capability resolution no longer requires an exact version and platform match. Measured against
the shipped evidence with the clients installed on the capture host:

|---|---|---|---|
| Claude Code | 2.1.278 | nothing | context, guards, nextTurn, livePush, replyRoute |
| Codex CLI | 0.153.4 | livePush only | context, guards, nextTurn, livePush |
| Gemini CLI | 0.60.0 | nothing | context, guards, nextTurn |

Codex CLI keeps `replyRoute` off: the 0.152.0 capture recorded it failing, and a recorded loss
applies forward until a later capture passes. On `linux-x64` and `win32-x64` every capability
of every adapter previously resolved to false, because every capture was taken on
`darwin-arm64`; they now read those captures.

## Limits

No new client capability is certified by this release, and no new capture was taken. What
changed is which clients the existing captures describe, which means a client that silently
breaks a capability on a version nobody captured will be offered bodies it may drop. Messages
carrying a `reply` or `acknowledge` obligation survive that, because their receipts stay open
until the agent answers; a `note` does not, which is the standing gap tracked for note
delivery.

The Kimi 0.42 loss of `PostToolUse` context, observed in the 2026-09-13 client survey, has no
capture at 0.42, so Kimi 0.42 inherits the 0.36.1 rows here. Recording that loss needs its own
capture.

`certificationFloor` is removed without a compatibility shim: an adapter built against the
previous SDK that declares the field fails validation with a message naming it.
