# ACC v0.14.0 release candidate evidence

This candidate ships the work merged to main after 0.13.0, which is all from #400: Kimi Code
`Stop` continuation and Kimi Web wake-only live delivery (#390), Codex sender permissions that
follow Kimi's live policy, and a Windows fix for the status-line offer observation.

The release adds a capability and keeps store contract 8, so it is a minor version with no data
migration. Managed-update protocol 2 is unchanged. This is candidate preparation, not
publication.

The detection shims avoid native service preparation, so these checks prove package and state

## Real Kimi Code 2.4.1, installed from the exact archive

Every case ran the real `kimi` 2.4.1 client with an isolated `HOME`, `KIMI_CODE_HOME` and ACC
data home, installed hooks from the extracted archive, and a deterministic local provider on
`127.0.0.1`. The provider is a stub: it answers a request that names an ACC message with an
`acc reply` tool call. It does not establish a Moonshot model's judgment.

| Case | Result |
|---|---|
| Kimi Web idle wake, busy queue, reply, duplicate, fallback/restart, exact binding (C01-C06) | 6 of 6 passed; owned processes stopped and temporary state removed |
| Token rotation with a fresh binding | woken |
| Session created in manual mode | queued, no provider request |
| Session bound in `yolo`, then switched to manual | queued, no provider request |
| Foreign session lock | queued, no provider request |
| Reclaimed (cold) session | queued |
| `kimi -p`, a question arriving mid-turn, `Stop` continuation | the continuation carried ACC's notice and the message id, never the body; `acc reply` acknowledged the message |

The recorded C01-C06 run names this archive's SHA-256. The same scenarios on the reviewed
#400 head are in [the review evidence](kimi-delivery-review-2026-11-01.md).

## Limits

- Kimi Web delivery was captured only with a pre-existing loopback server on darwin-arm64 in
  `yolo` mode. The lock or lease check to prompt submit race remains, because Kimi has no
  conditional warm-only submit.
- No real Codex session sent to Kimi Web in these runs; the Codex permission changes are covered
  by the package's unit and command tests.
- Publication remains a separate step after the release pull request merges.
