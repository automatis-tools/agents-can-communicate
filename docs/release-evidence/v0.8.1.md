# ACC v0.8.1 release evidence

Native live delivery is judged by the client's version and by the machine's own probe and
handshake, on every platform, and six defects found on the maintainer's machine right after
0.8.0 are fixed, among them the daemon of Codex CLI 0.157.1, which ships a symlinked control
socket and a new command line.

- Archive: `agents-can-communicate-0.8.1.tgz`, packed from that commit.
- Size: 472,108 bytes; 311 packed entries.
- SHA-256: `e32d414dd49512adbeee3071d696259920f0b5eee3d921d0c869c2a129d0b34a`.

`acc-mcp` present, doctor reporting six adapters, a workspace with no Git writing nothing into
the project, and client install/uninstall restoring topology, modes, links and bytes, with a

All 23 managed-update packed checks passed against real installed archives (automatic

## What changed since 0.8.0

Two merged pull requests, each with its own development record below the 0.8.0 section of
the CHANGELOG:

- **#204, fixes from the first real 0.8.0 update.** A session pin that names no client no
  longer holds its generation forever; a stopped Codex service is recognised and started in
  place by `acc install`; the daemon as Codex 0.157.1 presents it is recognised; `acc status`
  lists a closed participant only while its next turn would still show a message; a client
  that runs as a node script, Gemini CLI, is found behind the hook.
- **#206, native delivery judged by version alone.** The `nativeDelivery` contract is one
  `minimum` plus anchors without a platform; `platform_not_captured` and
  `prerelease_not_captured` are never produced again; Codex maintenance, service setup and
  live permissions lose their `darwin-arm64` checks; `lsof` is found where Linux keeps it and
  its Linux socket names are read; the docs state what may refuse live delivery.

## Mixed versions

The published 0.8.0 code, run from its own package through its entrypoint (it reported
`version 0.8.0`; after an update the old package's `acc` goes through the managed runtime and
would run the new code), and the installed 0.8.1 shared one store:

- 0.8.1 opened a Claude Code session, closed it with `endReason: "clear"`, sent it a
  question (`recipient_offline`, `endReason: clear`) and printed
  `waiting for a closed session: claude_code-… (cleared, 1)`;
- 0.8.0 read the status (2 participants), read the `installs.json` 0.8.1 had rewritten
  (doctor `ok`, policy `actionable`), synced the full store (5 events, the closed session's
  `extensions.endReason` intact) and sent a note into it;
- 0.8.1 read 0.8.0's write: the offline participant with `waiting: 2` and
  `unretrieved: { queued: 2, offered: 0 }`.

`STORE_VERSION` stays 6. Nothing new is written to the event store by this release; the
codes that changed are computed at read time or recorded in `installs.json`, which 0.8.0 reads
as it did.

## Compatibility notes

- An adapter declaring `nativeDelivery.minimumByPlatform` or an anchor `platform` fails
  validation with a message naming the replacement and the design. No shipped adapter did
  outside this repository.
- Stored native-attempt records that carry `platform_not_captured` or `prerelease_not_captured`
  keep reading; the vocabulary retains both as historical.
- Claude Code on native Windows keeps next-turn delivery: its inbox is a named pipe with an
  auth line, refused by the probe as a fact about the transport.
- A Codex 0.157.1 home with no standalone package installs a daemon package of its own under
  `packages/app-server-daemon/`; service setup still expects the standalone package there
  (#205). A home that already had the standalone package, as the maintainer's, keeps that
  layout under 0.157.1 and is fully recognised.

## Limits

Linux and Intel macOS are admitted to live delivery without a capture of their own: the probe
and handshake refuse a transport that does not answer, and a failed wake or queue add is a
recorded failed offer with durable fallback. The ubuntu CI job is the only Linux this code has
run on; it measured `lsof` at `/usr/bin/lsof`, the `/path type=STREAM` socket names, and the
same `ps -o lstart=` form, and it ran the packed Codex service preparation, its live
permissions and the Claude consent flow to the end. Unicode line separators in header fields
are tracked in #200.
