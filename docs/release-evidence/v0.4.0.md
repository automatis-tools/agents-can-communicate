trusted the project and five ACC hook definitions. After upgrading the same profile with
this exact archive, parsed project, TUI, hook and sandbox values matched, and the
stock `/hooks` surface showed all five definitions installed and active after restart.
No project trust prompt, hook trust prompt or additional trust action was required.
These are observed UI facts; copied files alone were not treated as activation.

Passed on the exact archive: clarification, first review, an explicit replacement decision,
changes-required verdict, correction, approval retrieved by the author, complete handoff, and
recovery by a fresh successor. All three native owners closed and no claims remained. All seven
fixture tests, an independent fixture oracle and the current-decision history query passed. The
three client processes exited successfully without operator interventions. Four deliberately damaged

open successor.

The scenario uses stock Claude Code 2.1.263 and Codex 0.153.4 with installed integrations
on macOS arm64 and a small non-Git project. It is a scripted integration scenario, not a
claim that every model will coordinate reliably on arbitrary work. It does not establish
idle live delivery or enlarge any adapter capability declaration.

## Scope and limits

- Restart and native trust remain client-controlled. The initial unmanaged 0.3.1 upgrade
  requires coordinated restart; an old process cannot be enrolled retroactively.
- Default inbox discovery is bounded and read-only. Retrieve an exact message to read its
  body and advance the receipt; history preserves superseded decisions and handoffs.
- An unidentified native process holds activation until its lifecycle resolves. Corrupt
  or ambiguous ownership is not evidence of process death.
- Legacy Codex sandbox settings are retained conservatively on uninstall when old markers
  cannot establish field ownership. The uninstall diagnostic reports this retention.
- macOS client observations do not certify native behavior on Linux. Windows is outside
  the package's supported OS list. Existing [capability evidence](../CAPABILITIES.md)
  retains its own version and platform limits.
- Large-history performance work is deferred to the next version.

Raw transcripts were not collected by the harness. Bounded metadata, synthetic fixture
messages, failed-candidate records, commands and mutation logs remain in the maintainer's
ignored `.docs` research directory. Superseded archives are not release artifacts.
