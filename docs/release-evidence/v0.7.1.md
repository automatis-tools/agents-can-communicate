# ACC v0.7.1 release evidence

A sender can now see where a message got to. This release shows every recipient's receipt on an
exact history read, counts what each participant has not fetched in `acc status`, and shows a
live offer that nothing followed once more at the recipient's next turn.

## What the release contains

- **Receipts on an exact history read.** `acc sync --scope history --message <id>` returns a
  `receipts` array beside the message: each recipient's `state`, `updatedAt` (the last state
  change) and `offer` - the transport that accepted it, when, and `repeatedAt` if the next turn
  showed it again. A receipt offered by an older ACC reads `offer: null`.
- **Unretrieved counts in status.** Each status row carries its participant's
  `unretrieved: {queued, offered}`, `counts.unretrieved` holds the workspace total, and the text
  line ends with `<n> offered, not retrieved` when that number is above zero.
- **One repeat of a live offer.** A direct message still `offered` through a live transport 15
  minutes after the offer is shown once more before the recipient's next turn, after new bodies,
  with `repeat: offered via <transport> at <timestamp>; no retrieval recorded` inside the
  untrusted block. A next-turn offer is never repeated: it is recorded only after the hook's
  output carried the body. An end-of-turn continuation never carries a repeat, and a client that
  cannot take next-turn bodies never asks for one.
- **Every skill** tells a sender how to check a receipt, and a recipient that a repeated message
  that asks for a reply or an acknowledgement still owes one.

## Mixed versions

An older ACC rejects an unknown event type or receipt field on read, so offer facts live in the
receipt's `extensions` and the repeat is another `message.offer_succeeded` with `repeat: true`.
`STORE_VERSION` stays 6.

Checked with installed archives, not with the source tree: the 0.7.1 tarball above and the
published 0.7.0, each installed with an isolated `ACC_DATA_HOME`, against one store. 0.7.1's core
recorded a live offer and, 16 minutes later on its clock, the repeat:

```text
0.7.1  status text while offered: "2 live; 0 claim(s); protection none; 1 offered, not retrieved"
0.7.0  status text while offered: "2 live; 0 claim(s); protection none"
0.7.0  sync --scope full events: ["workspace.materialised","session.opened","session.opened",
       "message.recorded","message.offer_succeeded","message.offer_succeeded(repeat)"]
0.7.0  inbox --message receipt: {... "state":"retrieved", "extensions":{"offer":{
       "transport":"codex-app-server", ..., "repeatedAt":"2026-09-25T06:30:31.535Z"}}}
0.7.1  history receipts: [{"recipientParticipantId":"beta","state":"retrieved", ...,
       "offer":{"transport":"codex-app-server", ..., "repeatedAt":"2026-09-25T06:30:31.535Z"}}]
```

0.7.0 read every event and receipt, and its own transition to `retrieved` kept the offer facts.

## Measured on real stores

A read-only census of every workspace store on the maintainer's machine, 2026-09-25, found 109
receipts: 69 acknowledged, 32 queued, 5 retrieved and 3 offered. The three offered receipts were
answers with no obligation, offered live. From a successful offer to the first retrieval or
acknowledgement: median 36 seconds, 90th percentile 14 minutes, maximum 24 minutes over 49 pairs.
The 15-minute threshold sits above that 90th percentile.

## Limits

- A receipt offered by an older ACC has no offer facts. It reads as `offer: null` and is never
  repeated.
- A repeat is recorded once per receipt. As with a first offer, two sessions of one participant
  can both show it before either commits, and a hook that runs out of time after writing does not
  commit it.
- A model that already handled a live-offered message it never acknowledged sees one duplicate
  block, labelled as a repeat. A Codex turn that outlasts the threshold can show the repeat in the
  same turn the daemon runs the queued original.
- The status suffix counts every offered receipt, including next-turn offers of notes that were
  shown whole and never fetched. The exact history read names the transport.
- Unicode line separators inside one-line header fields are tracked in #200.
- Native client activation is not established by local-registry or direct process checks; this
  release changes no adapter certification.
