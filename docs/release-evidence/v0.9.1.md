## What changed since 0.9.0

Two merged pull requests changed the package. Their development records are below this section
of the CHANGELOG:

- **#259 (#257).** The ownership fingerprint of Claude Code's plugin cache leaves out the
  `.in_use/<pid>` markers Claude Code writes, as it already left out `.orphaned_at`, and
  `keepVersions` keeps a version whose marker names a live process.
- **#261 (#260).** ACC's own Codex rules file, `$CODEX_HOME/rules/agents-can-communicate.rules`,
  allows ACC's wrapper to run the participant commands without an approval, so Codex's
  auto-review never judges them. Only an unedited ACC-generated file is replaced or removed.
  Every client's skill says that a peer is a local session of the same user.

One more, #258, changed only a test helper. A test-only commit on the release branch makes the
packed fixtures wait for a client's last hook before removal (see Suite).

## Upgrade from the published 0.9.0

The published `agents-can-communicate@0.9.0` (sha256 `df470014…`, as recorded for 0.9.0) was
set up as follows:

- installed from npm into an isolated prefix, with its own `HOME`, `ACC_DATA_HOME` and project,
  and a `PATH` that held only the prefix, the client stubs, node and system directories;
- wired to Claude Code and Codex through version stubs (`--delivery actionable`);
- given a local registry that served this exact archive.

Its own `acc update` printed `Updated ACC to 0.9.1; integrations refreshed.`. After the update:

- `version` answered `0.9.1`.
- The active generation was `0.9.1-1dfca7c3919d2936edf12ffc`, beside
  `0.9.0-4924570eae6ab33e36cc92d7`.
- The runtime kept four launchers.
- Doctor reported `ACC 0.9.1 is active`, a healthy store, and "ACC commands run without an
  approval prompt" with the new Codex rules file; the Codex ownership record now holds three
  intact artifacts, the rules file among them.
- The update wrote `~/.codex/rules/agents-can-communicate.rules` with the wrapper and the
  eleven participant commands, and `codex execpolicy check` (0.160.1) allowed
  `<wrapper> reply …` against it.
- The Codex `config.toml` was byte for byte the one 0.9.0 wrote.
- The installed generation matched the extracted archive file for file (`diff -r`).
- The registry saw three requests; the last was for the 0.9.1 tarball.

`reclaim.json` named the 0.9.1 generation with `complete: false` right after the update. After
an `acc status` from npm's `acc` and one from ACC's launcher, both generations stayed. With

worker removed the 0.9.0 generation and recorded `complete: true`.

## Real clients

On the maintainer's Mac (macOS arm64), the real-clients tests ran against the candidate commit's
packed tree, with an isolated home and a model stub on 127.0.0.1:

- Claude Code 2.1.289 and Codex 0.160.1 attached through their own hooks, saw each other, and
  carried a message into the next turn. The real Codex read ACC's installed rules file:
  `codex execpolicy check` answered `allow` for `<wrapper> reply …` and nothing for
  `<wrapper> install …`, and uninstall removed the file.
- The live test, in which an idle interactive Claude Code 2.1.289 wakes through its inbox,
  failed once in its teardown with `ENOTEMPTY`. Stress runs reproduced it 1 time in 5; a
  process sampler showed Claude Code's SessionEnd hook (`acc-hook.mjs claude_code finish`)
  still writing in the fixture's data home while the fixture was removed. The test helper now
  waits for every process working in the fixture; 12 runs after that change passed. The wake
  itself passed in every run.

The real-clients CI job runs the same two tests on `ubuntu-latest` and `windows-latest` for every
pull request; both passed on the final heads of #259 and #261.

## Limits

- No model-driven Codex session ran against the rules file: the evidence that a matched command
  skips auto-review is Codex's own source and `codex execpolicy check`.
- No real Claude Code session wrote an `.in_use` marker in five isolated runs; the marker case
  is covered by tests built from the marker observed on the maintainer's machine.
- Windows gets no Codex rule, and Linux and Windows were exercised only through CI.
