# Unreleased Codex sessions blocked from waking Claude Code

Implements [the 2026-09-27 design](../design/2026-09-27-codex-sandbox-claude-inbox.md) for
#213. Draft: the live capture and the candidate artifact are pending.

## What was measured before the change

- ACC 0.8.1, Codex CLI 0.157.1, Claude Code 2.1.283, macOS arm64. A Codex session that
  started after the profile was installed answered a Claude Code question with `acc reply`.
  The result said "live offer blocked by sender permissions; message remains queued". The
  reply reached Claude Code at its next turn through the next-turn hook.
- `acc doctor` on the same machine said "Codex CLI outgoing live delivery: local socket
  permissions configured for new sessions".
- The ACC-owned profile allowed `/tmp/acc-ch-501` and
  `~/.codex/app-server-control/app-server-control.sock`. Claude Code 2.1.283 binds its inbox at
  `${XDG_RUNTIME_DIR || CLAUDE_CODE_TMPDIR || "/tmp"}/cc-socks/<pid>.sock` (fallback
  `/tmp/cc-socks-<uid>/<pid>.sock`), read from the executable. The socket observed on this
  Mac was `/tmp/cc-socks/<pid>.sock`.
- `codex sandbox -P` on 0.157.1, in a temporary `CODEX_HOME`: a missing grant path is kept
  as written, and the sandbox compares resolved paths. A `/tmp/d` grant for a directory created
  after the policy was built was EPERM, and a `/private/tmp/d` grant was allowed. The full
  table is in `packages/adapter-codex/COMPATIBILITY.md`.

## What changed

- `adapter-sdk/capabilities.mjs`: `defineAdapter` accepts an optional `inboundSockets`
  function and refuses any other value.
- `adapter-claude-code/inbox-socket-directories.mjs` declares the inbox directories: the
  environment's primary one, `/tmp/cc-socks`, `/tmp/cc-socks-<uid>` (`$PREFIX/tmp` under
  Termux), `/run/user/<uid>/cc-socks` on Linux, and nothing on Windows. Antigravity declares
  the ACC channel directory, and Codex declares its control socket.
- `installer/receiver-sockets.mjs` composes every adapter's declaration.
  `cli/install-command.mjs` `clientContext` adds it as `receiverSockets` for the runtime
  platform. Install, doctor and the managed refresh read it.
- `adapter-codex/live-permissions.mjs`: the profile allows the control socket and every
  receiver socket. `grantPath` resolves each grant's existing parent and keeps the last
  component. `configured` requires every grant. An owned but incomplete profile names the
  missing paths and `run acc install --adapter codex`. An owned, outdated unit is rewritten
  under a recorded `off` policy unless a custom policy sits beside it. The setup text names
  other clients' session inboxes.
- `adapter-codex/install.mjs` passes `receiverSockets` to install and detection.

## Measured after the change (no model session)

From this branch, in temporary homes, with a version shim answering `codex-cli 0.157.1` and
`CLAUDE_CODE_TMPDIR` pointing at a temporary directory:
`acc install --adapter codex --delivery actionable` wrote grants for `/private/tmp/acc-ch-501`,
the control socket, `/private/tmp/cc-socks`, `/private/tmp/cc-socks-501` and the resolved
`$CLAUDE_CODE_TMPDIR/cc-socks`. `acc doctor` printed "outgoing live delivery: local socket
permissions configured". The real `codex sandbox -P acc-workspace` connected to a listener at
`$CLAUDE_CODE_TMPDIR/cc-socks/4242.sock`. It connected again when the directory was created
only after the policy was built. The same connect under a profile with 0.8.1's two grants
returned EPERM.

## Tests

Each new test was seen failing for its stated reason before the change that made it pass.

- `packages/adapter-sdk/test/capabilities.test.mjs`: a non-function `inboundSockets` is
  refused.
- `packages/adapter-claude-code/test/inbox-socket-directories.test.mjs`: macOS, Linux with
  and without `XDG_RUNTIME_DIR`, the XDG-over-TMPDIR order, empty and relative values,
  Termux and Windows, and the adapter's declaration from its context.
- `packages/adapter-antigravity/test/adapter.test.mjs`: the relay directory is declared.
- `packages/installer/test/receiver-sockets.test.mjs`: union, order, absolute paths only.
- `packages/cli/test/install-command.test.mjs` and `doctor-passes-env-to-detection.test.mjs`:
  the context carries every receiver, and a `win32` runtime declares no inbox directory
  whatever the host.
- `packages/adapter-codex/test/live-permissions-receivers.test.mjs`: grant spelling with an
  injected resolver, including the link case. The profile allows every receiver, and doctor
  requires every one. Also covered: the exact bytes ACC 0.8.1 wrote
  (`test/fixtures/acc-0.8.1-outgoing-profile.toml`, generated by the unchanged v0.8.1 module)
  read as owned and incomplete with the fix named; re-install on and off rewrites them and
  uninstall restores the original; a user-edited profile, and one with a user sandbox
  setting beside it, stay as they are; a fresh off install adds nothing; the setup text.
- `packages/adapter-codex/test/live-permissions-install.test.mjs`: install writes, and
  detection requires, the receivers from the context. The existing control-socket assertion
  now expects the resolved Codex home, because macOS keeps temporary directories behind
  `/var` -> `/private/var`.
- `packages/cli/test/managed-runtime-refresh.test.mjs`: the managed refresh rewrites a
  Codex profile written for fewer receivers.
- `tests/acceptance/codex-live-permissions-packed.test.mjs`: the packed install allows
  `cc-socks`. An older profile makes the packed doctor name the missing paths, and packed
  `acc install --adapter codex` under a recorded `off` policy makes it configured.

## Mutations

Each was applied alone, caught by the tests named, and reverted:

| Mutation | Caught by |
|---|---|
| `defineAdapter` accepts a non-function `inboundSockets` | capabilities |
| Claude Code: no Linux `/run/user` default; TMPDIR before XDG; no Windows refusal; no Termux prefix; relative paths kept; adapter ignores `env` | inbox-socket-directories (one test each) |
| Antigravity or Codex declares nothing | adapter, live-permissions-receivers |
| composition keeps relative paths / leaves the list unsorted | receiver-sockets |
| `clientContext` composes from no adapter / drops the platform | install-command, doctor-passes-env, managed-runtime-refresh, packed |
| doctor drops the runtime platform | doctor-passes-env (the `win32` assertion) |
| no resolved spelling; resolving the link itself | live-permissions-receivers, -install |
| receivers ignored; coverage not required | live-permissions-receivers, -install, managed-runtime-refresh |
| no refresh under `off`; refresh despite a user policy | live-permissions-receivers, packed |
| diagnostic without the missing paths; outdated profile described as absent | live-permissions-receivers, -install |
| install or detection drops `receiverSockets` | live-permissions-install |
| refresh context without receivers | managed-runtime-refresh |
