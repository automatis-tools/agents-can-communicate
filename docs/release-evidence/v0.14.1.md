# ACC v0.14.1 release candidate evidence

This candidate ships the work merged to main after 0.14.0: #419, which makes a held note explain
itself and gives the Codex lease refresh the same five-second bound as an offer, and the
release-procedure step from #417.

The release keeps store contract 8 and managed-update protocol 2, so it is a patch version with
no data migration. This is candidate preparation, not publication.

## Real clients

Claude Code 2.1.319, Codex 0.167.0 and Antigravity 1.5.3 ran as real terminal sessions in
isolated client homes on macOS arm64, with the archive of #419
(`f27028308743ee0f25e1e06c69c2fa4754ec5c00e7beedd438fd052ba14c5637`). Commit A differs from that
archive's source in packed paths only by version numbers. Each run gave the three sessions one
deploy lane and sent one sentence to Claude Code.

- With a repository instruction to use a request when another session has to act, all three
  deploys ran in sequence with no overlap, at load average 178. A Codex session idle for 4.5
  minutes, past its 120-second lease, took a live offer through `codex-app-server` and acted on it.
- Without that instruction, two runs each left one feature unshipped. Claude Code read the skill
  sentence about notes and its first message was still a `note`. The CLI reported the note as held
  until the next turn in both runs. In one run the next message to a peer was a `request`.

## Full suite

With commit B's evidence in place, the full suite ran 4127 tests under Node 24.4.0 at load average
41–94. Of those, 4117 passed, 10 were skipped and none failed.

## Limits

- The new refresh bound was observed under high load in one run with a real client.
- The skill sentence did not change the model's first choice in these runs. The change makes the
  outcome of a held note accurate.
- Publication remains a separate step after the release pull request merges.
