# ACC v0.13.0 release candidate evidence

This candidate ships the work merged to main after 0.12.2. The headline is store contract 8
(#305, #306, #307). It also carries the update fixes for #406 and #402, the client-directory fixes
for #148 and #409, Codex approval guidance, the ChatGPT Work Mode guidance (#316) and
contributing guidance (#175).

Store contract 7 becomes 8, so this release is a minor version. The update waits for client
sessions on older ACC to end and then migrates every workspace's store by itself. Managed-update
protocol 2 is unchanged. This is candidate preparation, not publication.

## Upgrade from published 0.12.2

The previous archive was downloaded from npm. Its SHA-256 matched the published 0.12.2 record:
`d1fa01057ad07394bc60f76ca718d2268d6fac7a4c5802bc33f212e21db058c4`.

Setup:
- isolated home, data home, npm prefix and npm cache;
- client detection shims for Claude Code 2.1.316 and Codex 0.166.0;
- a local registry that served the exact candidate as 0.13.0.

Fifteen checks passed:
- 0.12.2 installed both integrations, and the automatic-update opt-out was set.
- Two CLI participants attached. The sender recorded a question while the store was on
  contract 7.
- `acc update --yes` activated 0.13.0, the stable CLI reported 0.13.0, and the opt-out survived.
- After the update:
  - the peer saw the contract-7 question and replied;
  - the sender received the reply;
  - the workspace's store identity reported contract 8.
- `.claude/settings.json` and `.codex/config.toml` kept their bytes.
- All 381 archive files were installed in the active generation with the same SHA-256.
- The stable CLI answered 0.13.0 after the npm installation was removed.

The detection shims avoid native service preparation, so these checks prove package and state
continuity, not native activation.

With the data home under `/tmp`, a symbolic link on macOS, the refresh rewrote the Codex
`writable_roots` entry from `/tmp/...` to `/private/tmp/...`. Install records the path as given,
and the refresh records its resolved form. The directory is the same. Under a resolved path,
all fifteen checks passed, the byte check included.

## The maintainer's data home, copied

The candidate's own code ran against a copy of the maintainer's data home. The copy holds 821 MB
and 73 workspaces. The real data home was only read.

- `listActivationBlockers` for contract 8 named seven processes. Each one was a live client
  process holding a contract-7 binding:
  - five Claude Code sessions;
  - the Codex app inside ChatGPT.app;
  - a Codex app-server daemon.

  None was a stale binding. Activation on that machine waits for those sessions to end, as
  designed.
- `migrateFilesystemStore` moved all 73 stores to contract 8:
  - no message file changed a byte;
  - every store was healthy afterwards;
  - none failed.

## Limits

- No new live capability or captured minimum is declared.
- The migration was run on a copy, outside the managed runtime's own pass. The upgrade
  preflight covers that pass on an isolated install.
- A path recorded through a symbolic link is rewritten in its resolved form on the first refresh.
- Publication remains a separate step after the release pull request merges.
