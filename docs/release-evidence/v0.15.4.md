# ACC v0.15.4 release candidate evidence

This candidate ships the work merged to main after 0.15.3: #418, #211, #200, #149, #146, #150,
#143, #135 and #132, and the test change from #325. Each change has its own development evidence
in this directory.

The release keeps store contract 8 and managed-update protocol 2, so it is a patch version with
no data migration. This is candidate preparation, not publication.

## Exact artifact

- Source: clean commit `f05c6b51b90fafe527f0704d8dc5ada1965187be`, on main `9102f651` (PR #439).
- Archive: `agents-can-communicate-0.15.4.tgz`, 671,223 bytes, 397 files.

- The root manifest, fifteen workspaces and two versioned embedded manifests declare 0.15.4. So
  does the lockfile. The Codex and Kimi Code plugin manifests carry no version in source; ACC
  stamps them at install.
- `npm ci` and the syntax check of 940 modules passed before commit A.
- The documentation-reader audit pin was refreshed after commit A. The external reader list is
  unchanged: no file added or changed since 0.15.3 reads documentation.

The exact archive passed `scripts/verify-package.mjs`, which checks:
- bundled workspaces, the certification inventory and packed links;

## Upgrade from published 0.15.3

The previous archive was downloaded from npm. Its SHA-256 matched the published 0.15.3 record:
`7e582bc6350e104a750cf58d783eaaa8142639fff0639947afd4e49ebb568fc6`.

Setup:
- isolated home, data home, npm prefix and npm cache, under a path without symbolic links;
- real client executables on `PATH` through a symlink-only directory: Claude Code 2.1.331,
  Codex 0.172.0, Kimi Code 2.5.3 and Gemini CLI 0.60.0;
- a local registry that served the exact candidate as 0.15.4, and then the same archive
  re-versioned as 0.15.5;
- a closed local port standing in for an unreachable registry.

Under 0.15.3, Claude Code, Kimi Code and Gemini CLI were installed with defaults, and Codex with
`--delivery off`. Twenty-eight checks passed:
- 0.15.3 installed all four integrations. Its Kimi Code plugin preloaded the skill through
  `sessionStart`, and its Gemini CLI extension named `skills/acc/SKILL.md` as the context file.
- `acc update --yes` activated 0.15.4 with the notice "ACC 0.15.4 is active."
- Codex's hooks plugin kept its 0.15.3 copy with the same content hash, by a port of Codex's
  `plugin_fingerprint.rs`. The skill plugin moved to 0.15.4 beside its 0.15.3 copy. ACC's block
  in `config.toml` still enables the hooks plugin.
- Kimi Code's plugin manifest now only lists the skill, stamped 0.15.4, and the skill file is in
  place.
- Gemini CLI's extension now names `ACC.md`, under 600 bytes, and still carries the skill.
- Claude Code's `settings.json` kept its bytes.
- With no Codex service in that home, doctor reported hook readiness as unverified. It started
  no Codex process and left `config.toml` byte for byte.
- A question recorded under 0.15.3 crossed the update. The peer saw it and replied, the sender
  received the reply, and the store stayed on contract 8.
- All 397 archive files were installed in the active generation with the same SHA-256.
- The update worker, run against the closed port with a due check, named the cause
  `fetch failed (ECONNREFUSED)`. The next due pass against the local registry cleared it.
- The update to 0.15.5 left the hooks plugin on its 0.15.3 copy with the same hash.
- The stable CLI answered 0.15.5 after the npm installation was removed.

The same check first ran with the data home under `/tmp`, which is a link to `/private/tmp` on
macOS. There the update rewrote the hook shim's data-home line with the resolved path, so Codex's
hooks plugin moved to a new copy and three hooks-plugin checks failed. The 0.15.3 preflight gave
the same three failures under `/tmp`, so 0.15.4 does not introduce this. It is filed as #440.
