# ACC v0.15.6 release candidate evidence

This candidate ships the work merged to main after 0.15.5: #453. Its development evidence is in
[doctor-offline-session-2026-11-25.md](doctor-offline-session-2026-11-25.md).

The release keeps store contract 8 and managed-update protocol 2. It is therefore a patch version
with no data migration. This document records candidate preparation, not publication.

## Upgrade from published 0.15.5

The previous archive was downloaded from npm. Its SHA-256 matched the published 0.15.5 record:
`ec0b9ac1e2896920c40bd20f02d313d81d62a344030acff2d36fe4aaaf9821b9`.

Setup:
- an isolated home, data home, npm prefix and npm cache;
- real client executables on `PATH`, through a directory that holds only symbolic links: Claude
  Code 2.1.332, Codex 0.172.0, Kimi Code 2.5.3 and Gemini CLI 0.60.0;
- a local registry that served the exact candidate as 0.15.6, and then the same archive
  re-versioned as 0.15.7;
- a closed local port in place of an unreachable registry.

Under 0.15.5, Claude Code, Kimi Code and Gemini CLI were installed with their defaults. Codex was
installed with `--delivery off`. All twenty-six checks passed:
- 0.15.5 installed all four integrations, and its doctor reported hook readiness as unverified
  without a Codex service.
- `acc update --yes` activated 0.15.6 with the notice "ACC 0.15.6 is active."
- Codex's hooks plugin kept its 0.15.5 copy with the same content hash. The hash comes from a port
  of Codex's `plugin_fingerprint.rs`. The skill plugin moved to 0.15.6 beside its 0.15.5 copy.
  ACC's block in `config.toml` still enables the hooks plugin.
- Kimi Code's plugin manifest still lists only the skill. Gemini CLI's extension still names the
  short `ACC.md`. Claude Code's `settings.json` kept its bytes.
- With no Codex service in that home, doctor reported hook readiness as unverified. It started
  no Codex process and left `config.toml` unchanged byte for byte.
- A question recorded under 0.15.5 crossed the update. The peer saw it and replied, the sender
  received the reply, and the store stayed on contract 8.
- All 398 archive files were installed in the active generation with the same SHA-256.
- The update worker ran against the closed port with a due check and named the cause
  `fetch failed (ECONNREFUSED)`. The next due pass against the local registry cleared it.
- The update to 0.15.7 left the hooks plugin on its 0.15.5 copy with the same hash.
- The stable CLI answered 0.15.7 after the npm installation was removed.

The same check ran a second time with the work directory reached through a symbolic link, so
that the data home path goes through a link. All twenty-six checks passed again.

## Real clients and other platforms

- #453 changes what `acc status` and `acc doctor` report for an offline session. It changes no
  client integration file. The changed doctor code, run read-only on a real macOS store, named
  an exited Codex 0.167.0 session offline; see the development evidence.
- Linux and Windows run the change in CI: the full suite on `ubuntu-latest`, `macos-latest` and
  `windows-latest`, and the real-clients job on Linux and Windows, passed for PR #454.

## Limits

- The upgrade check opened no Codex, Kimi Code or Gemini CLI session. It proves the files that
  each client reads, not the behaviour of a session that starts after the update.
- Linux and Windows ran in CI only.
