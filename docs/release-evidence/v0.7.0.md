# ACC v0.7.0 release evidence

A workspace store can now give space back. This release adds `acc prune`, a bounded automatic
reclaim of what the store keeps and never reads, and history trimming with a reported boundary.
It also stops `acc status` reporting finished work as current.

## What the release contains

- **`acc prune`** reports what a workspace no longer needs and reclaims it only with `--apply`.
  The reporting run is the default because this is the one command that takes records out of a
  store. Classes: sessions, intents, claims, participants.
- **A bounded automatic pass** reclaims retired transaction journal entries and superseded
  retention markers when a store is opened. Both are provably unread - `retireJournalEntry`
  never unlinks, and `completeJournal` wrote a marker nothing reads - which is what lets them go
  without an operator asking. `acc doctor --repair` reclaims without the per-pass bound.
- **History trimming** to a cursor the operator names, with `sync` reporting `trimmedThrough` so
  a caller whose cursor precedes the boundary can tell it was served a short page.
- **`acc status` no longer reports a finished intent as current work**, and the resource hints of
  finished work no longer raise claim conflicts.
- **Accepted staging files** live in their own directory and are swept by detaching it, so a
  store's `tmp/` no longer grows by one file per published record.
- **A degraded Antigravity relay ask** is no longer spent by a greeting, and a synchronous throw
  from the activation hint no longer drops the hook's line.

## Measured on real stores

On the maintainer's machine, 2026-09-25, across 32 workspace stores: **44,415 files before,
4,454 after**. One workspace went from 14,434 files to 1,437; another from 19,219 to 521;
another from 13,569 to 66. Every store opened and reported healthy afterwards, with 402 records
readable across all of them, and `acc status` and `acc inbox` answered normally.

Record removal ran only in the maintainer's own repository workspace, where presence could be
judged. Every other workspace had only provably-unread bookkeeping reclaimed.

## Limits

- **An ACC older than this release does not know about `trimmedThrough`.** Served a cursor below
  a trim boundary it returns what it can find, without reporting that anything is missing. That
  is why trimming history is always an explicit operator act and never automatic.
- **Trimming is not reversible.** The dry run is the default for that reason, and a boundary past
  what a store has issued is refused rather than clamped.
- No store layout version is introduced, and nothing refuses to open an older store. A store that
  has never published into `stage/` is swept rather than refused.
- Native client activation is not established by local-registry or direct process checks; it is
  captured separately on supported real clients, and this release changes no adapter
  certification.
