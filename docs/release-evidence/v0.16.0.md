# ACC v0.16.0 release candidate evidence

This candidate ships the work merged to main after 0.15.6: #145 and #147. Its development
evidence is in [withdraw-pending-2026-11-25.md](withdraw-pending-2026-11-25.md) and
[inbox-wait-2026-11-25.md](inbox-wait-2026-11-25.md).

The release adds two commands, `acc withdraw` and `acc inbox --wait`, so it is a minor version.
It keeps store contract 8 and managed-update protocol 2, with no data migration. This document
records candidate preparation, not publication.

- Source: clean commit `7642b80f236d307aeec8e4321a5e1229345bac0f`, on main `30920b0a` (PR #456).
- Archive: `agents-can-communicate-0.16.0.tgz`, 681,217 bytes, 401 files.

- SHA-1: `9f85aa2698b1202db2bc74b88d4ba2e162ceb82a`.
- Node 24.4.0, npm 11.4.2, macOS arm64.
- The root manifest, fifteen workspaces, two versioned embedded manifests and the lockfile
  declare 0.16.0.
- `npm ci` and the syntax check of 956 modules passed before commit A.
- The documentation-reader audit pin was refreshed after commit A. The external reader list did

The exact archive passed `scripts/verify-package.mjs`. That script checks:

## Upgrade from published 0.15.6

The previous archive was downloaded from npm. Its SHA-256 matched the published 0.15.6 record:
`4153ef95941c6bc0edc97f948a84484383d9bd90877fc5fd4e0abeae30853973`.

Setup:
- an isolated home, data home, npm prefix and npm cache;
- real client executables on `PATH`, through a directory that holds only symbolic links: Claude
  Code 2.1.332, Codex 0.172.0, Kimi Code 2.5.3 and Gemini CLI 0.60.0;
- a local registry that served the exact candidate as 0.16.0, and then the same archive
  re-versioned as 0.16.1;
- a closed local port in place of an unreachable registry.

Under 0.15.6, Claude Code, Kimi Code and Gemini CLI were installed with their defaults. Codex was
installed with `--delivery off`. All thirty-one checks passed:
- 0.15.6 installed all four integrations, and its doctor reported hook readiness as unverified
  without a Codex service.
- `acc update --yes` activated 0.16.0 with the notice "ACC 0.16.0 is active."
- Codex's hooks plugin kept its 0.15.6 copy with the same content hash. The hash comes from a port
  of Codex's `plugin_fingerprint.rs`. The skill plugin moved to 0.16.0 beside its 0.15.6 copy.
  ACC's block in `config.toml` still enables the hooks plugin.
- Kimi Code's plugin manifest still lists only the skill. Gemini CLI's extension still names the
  short `ACC.md`. Claude Code's `settings.json` kept its bytes.
- With no Codex service in that home, doctor reported hook readiness as unverified. It started
  no Codex process and left `config.toml` unchanged byte for byte.
- A question recorded under 0.15.6 crossed the update. The peer saw it and replied, the sender
  received the reply, and the store stayed on contract 8.
- On that store, `acc inbox --wait 2` returned `arrived: false` while a request recorded under
  0.15.6 was still pending. A second wait returned `arrived: true` about 2.5 seconds after it
  started, once the sender recorded a new note.
- The sender withdrew the request recorded under 0.15.6. It left the peer's inbox, and the peer
  received the note "Withdrawn: second" with the reason as its body.
- All 401 archive files were installed in the active generation with the same SHA-256.
- The update worker ran against the closed port with a due check and named the cause
  `fetch failed (ECONNREFUSED)`. The next due pass against the local registry cleared it.
- The update to 0.16.1 left the hooks plugin on its 0.15.6 copy with the same hash.
- The stable CLI answered 0.16.1 after the npm installation was removed.

The same check ran a second time with the work directory reached through a symbolic link, so
that the data home path goes through a link. All thirty-one checks passed again.

## Real clients and other platforms

- #145 and #147 add CLI commands and change the `acc` skill text in all six client copies: its
  review wait uses `inbox --wait 60`. They change no hook, configuration or other client
  integration file, so Codex's hooks plugin keeps its files.
- A 0.15.6 reader of a store with a withdrawal was checked during development: it reads the
  closed receipt as acknowledged and stops showing the withdrawn message. See the #145
  development evidence.
- Linux and Windows run the changes in CI: the full suite on `ubuntu-latest`, `macos-latest` and
  `windows-latest`, and the real-clients job on Linux and Windows, passed for PRs #456 and #457.

## Full suite

With commit B's evidence in place, the full suite ran 4254 tests under Node 24.4.0 at load average
8–30. Of those, 4241 passed, 13 were skipped and none failed.

## Limits

- The upgrade check opened no Claude Code, Codex, Kimi Code or Gemini CLI session. It proves the
  files that each client reads and the CLI behaviour, not how a client session follows the new
  skill text.
- Linux and Windows ran in CI only.
