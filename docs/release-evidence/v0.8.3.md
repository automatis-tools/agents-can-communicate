release, npm could answer the download from a package document it had cached before the
registry listed the release, and the update failed with `ETARGET`.

## What changed since 0.8.2

One merged pull request, with its development record below the 0.8.2 section of the

- **#222, an update right after a release** (#221). The download runs `npm install

  downloaded archive is still checked against the integrity that discovery returned.

## The defect on the maintainer's machine

On 2026-09-28, `acc update` from 0.8.1 to the just-published 0.8.2 failed with `ETARGET`.
The registry listed 0.8.2 at 22:24:47Z. npm had cached the package document without it at
22:22:54Z with `max-age=300`. The update at 22:25:57Z logged `cache hit`. The same update with
`npm_config_prefer_online=true` at 22:27:18Z, while that cache entry was still fresh, logged
`cache updated` and activated 0.8.2. This release makes that setting part of the download.

## Upgrade from the published 0.8.2

The published `agents-can-communicate@0.8.2` was installed from npm into an isolated prefix
with its own `HOME`, `ACC_DATA_HOME` and project, wired to Claude Code and Codex through version
stubs (`--delivery actionable`), and given a local registry serving this exact archive. Its own
`acc update` printed `Updated ACC to 0.8.3; integrations refreshed.`: `version` answered
`0.8.3`, the active generation was `0.8.3-ed06e6f8519ec18da9323742` beside the kept
`0.8.2-b44fb970407188c0a0d41009`, the runtime kept four launchers, and doctor reported
`ACC 0.8.3 is active` with Codex outgoing delivery configured. The Codex profile kept the same
four grants. The installed generation matched the extracted archive file for file
(`diff -r`). The registry saw three requests, the last for the 0.8.3 tarball.

## Compatibility notes

- The update to 0.8.3 is downloaded by the installed version. An install on 0.8.2 or older can
  still meet `ETARGET` right after this release; `npm_config_prefer_online=true acc update`
  avoids it, as `UPGRADING.md` says. Updates performed by 0.8.3 and later need no setting.
- No store, hook, client-integration or status change.

## Limits

No real-client session was run for this release: nothing a client runs changed. The fix was
measured on the maintainer's machine through the equivalent npm setting and by the packed
check, not by an update performed by the released 0.8.3 itself.
