# ACC v0.15.2 release candidate evidence

This candidate ships the work merged to main after 0.15.1: #425, which makes a failed background
update name its cause and clears that notice once a later check succeeds.

The release keeps store contract 8 and managed-update protocol 2, so it is a patch version with
no data migration. This is candidate preparation, not publication.

## Exact artifact

- Source: clean commit `ad4df1ae70216a8c2a417377c6945c118c204816`, on main `47d89151` (PR #425).
- Archive: `agents-can-communicate-0.15.2.tgz`, 659,952 bytes, 392 files.
- SHA-256: `9e3957955fe174cb8e4704b3450f79603c78332461654295fe56c88c0de4633f`.
- SHA-1: `f0fbe66ed6c09a7c0abda49a9ac153b851246233`.
- Node 24.4.0, npm 11.4.2, macOS arm64.
- The root manifest, fifteen workspaces and two versioned embedded manifests declare 0.15.2. So
  does the lockfile. The two Codex plugin manifests carry no version in source; ACC stamps them
  at install.
- `npm ci` with a release-only cache and the syntax check of 923 modules passed before commit A.
- The documentation-reader audit pin was refreshed in commit A. The external reader list is
  unchanged.

The exact archive passed `scripts/verify-package.mjs`, which checks:
- bundled workspaces, the certification inventory and packed links;
- all four binaries, doctor and a non-Git workspace;

Source packed from commit A passed all 25 managed-update checks in

## Upgrade from published 0.15.1

The previous archive was downloaded from npm. Its SHA-256 matched the published 0.15.1 record:
`860c533671061909a8f48a094a055a5f0b297ffe16957531899252373d8104d2`.

Setup:
- isolated home, data home, npm prefix and npm cache;
- real client executables on `PATH` through a symlink-only directory: Claude Code 2.1.330 and
  Codex 0.171.0;
- a local registry that served the exact candidate as 0.15.2, and then the same archive
  re-versioned as 0.15.3;
- a closed local port standing in for an unreachable registry.

Under 0.15.1, Claude Code was installed with no `--delivery` and Codex with `--delivery off`.
Twenty-three checks passed:
- 0.15.1 installed both integrations, with the hooks in `agents-can-communicate-hooks`.
- 0.15.1's own update worker, run against the closed port with a due check, left its cause-less
  notice "Automatic update could not finish; the previous runtime was kept. Run acc update for
  details."
- `acc update --yes` activated 0.15.2, and the activation replaced that notice with
  "ACC 0.15.2 is active."
- The hooks plugin kept its 0.15.1 copy with the same content hash, by a port of Codex's
  `plugin_fingerprint.rs`. The skill plugin moved to 0.15.2 beside its 0.15.1 copy. ACC's block
  in `config.toml` still enables the hooks plugin.
- Claude Code's `settings.json` kept its bytes.
- A question recorded under 0.15.1 crossed the update. The peer saw it and replied, the sender
  received the reply, and the store stayed on contract 8.
- All 392 archive files were installed in the active generation with the same SHA-256.
- 0.15.2's own update worker, run against the closed port with a due check, recorded
  `Automatic update could not finish: fetch failed (ECONNREFUSED).`, and `acc doctor` showed it.
  `acc update --check` left it in place. The next due pass against the local registry cleared it.
- The update to 0.15.3 left the hooks plugin on its 0.15.1 copy with the same hash.
- The stable CLI answered 0.15.3 after the npm installation was removed.

No Codex session was opened in this run, so it proves the files Codex trusts, not the trust
dialog itself.

## Real clients

On 2026-11-22 the maintainer's Mac ran a three-session scene on published 0.15.1 with Claude Code
2.1.330, Codex 0.171.0 and Antigravity CLI 1.5.7: one request to Claude Code produced three
deploys in sequence through ACC requests, with live wake-ups in Codex and Antigravity. Commit A
differs from 0.15.1 by `packages/cli/src/managed-runtime/worker.mjs` and its tests, by version
numbers, by the `docs/UPGRADING.md` section and by the documentation-reader pin. The changed
file runs only in the update worker and `acc update`.

## Full suite

With commit B's evidence in place, the full suite ran 4154 tests under Node 24.4.0 at load average
5–9. Of those, 4143 passed, 11 were skipped and none failed.

## Limits

- The original failure behind the stale notice on the maintainer's Mac was never recorded, so it

- Codex 0.171.0 ran in the upgrade check without a session; the trust dialog itself was not
  opened.
- Linux and Windows ran in CI only.
