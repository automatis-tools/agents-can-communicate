## Regression gates and mutations

Before implementation, three new tests failed on the missing admission contract,
the compatible live lease incorrectly blocking activation, and the missing pending
contract. After implementation, the focused checks passed.

Six deliberate mutations each failed the intended gate:

- Removing recovery lost new-process and pending contracts.
- Discarding normalized leases restored the false live-process blocker.
- Skipping the generation fingerprint trusted changed executable bytes.
- Replacing explicit contracts erased a known conflicting declaration.
- Accepting a string contract allowed invalid metadata into a new lease.
- Omitting the new immutable-launcher dependency broke installed execution.

Every mutation was restored. The development run before the version bump passed
all nine focused tests, including two installed Channels surviving an update.
The broader managed-runtime
run passed all 28 tests, including unknown and incompatible holds remaining
blocked. A separate read-only review found no blocking defects.

The retained mutation report is `mutations.json` in the diagnostic directory,
SHA-256 `2a92710a92757c8c90e1175d56bc2893d2d2df39b20bae5221696af78ef6de70`.

The first full suite reported 2,210 passes, two failures and one skip across
2,213 tests. Both failures came from the six-module verification lists described
above. After correction, all four affected checks passed. Two further mutations
proved that the security scan rejects a remote network import in the recovery
module and the capture test detects a skipped recovery-module byte comparison.
The restored checks passed again, and a read-only review found no weakened gate.
The report is `gate-mutations.json`, SHA-256
`81ee101f8e10a63a3bca7412f58b2e582f1c43f4002dde1c14da794b71a8cf40`.

## Recovery limits and final gates

An old updater with an already pending release retries that release before
checking npm again. Users in this state must install the new global CLI, then
run `acc update`. A missing contract is recoverable only when the referenced
managed generation declares one and its complete content hash matches. Explicit
contracts remain historical facts. Unverifiable generations and unknown native
bindings remain holds; no user process is terminated and no live lease is edited.

Existing delivery choices remain in effect. The release does not grant client
trust or enable previously disabled incoming delivery. The complete-setup flow
introduced in 0.5.4 remains available through explicit installation.

The full suite runs after the evidence commit, as required by
[Releasing](../RELEASING.md). The pull request records that pre-push result and
hosted CI results. The scoped checks above do not claim those later results.
