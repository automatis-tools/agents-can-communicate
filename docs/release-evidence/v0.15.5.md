# ACC v0.15.5 release candidate evidence

This candidate ships the work merged to main after 0.15.4: #440, #445, #446 and #449. It also
carries two verification changes. #444 makes package verification name every client-home entry
that was not restored, for #442. #451 adds the live Codex daemon check to CI, for #251. Each
product change has its own development evidence in this directory.

The release keeps store contract 8 and managed-update protocol 2. It is therefore a patch version
with no data migration. This document records candidate preparation, not publication.

## Upgrade from published 0.15.4

The previous archive was downloaded from npm. Its SHA-256 matched the published 0.15.4 record:
`673e05f6d09fcce55fefee3fd7b878dcf9351a1e3fc192052604fac83b6d9531`.

Setup:
- an isolated home, data home, npm prefix and npm cache;
- real client executables on `PATH`, through a directory that holds only symbolic links: Claude
  Code 2.1.331, Codex 0.172.0, Kimi Code 2.5.3 and Gemini CLI 0.60.0;
- a local registry that served the exact candidate as 0.15.5, and then the same archive
  re-versioned as 0.15.6;
- a closed local port in place of an unreachable registry.

Under 0.15.4, Claude Code, Kimi Code and Gemini CLI were installed with their defaults. Codex was
installed with `--delivery off`. All twenty-six checks passed:
- 0.15.4 installed all four integrations, and its doctor reported hook readiness as unverified
  without a Codex service.
- `acc update --yes` activated 0.15.5 with the notice "ACC 0.15.5 is active."
- Codex's hooks plugin kept its 0.15.4 copy with the same content hash. The hash comes from a port
  of Codex's `plugin_fingerprint.rs`. The skill plugin moved to 0.15.5 beside its 0.15.4 copy.
  ACC's block in `config.toml` still enables the hooks plugin.
- Kimi Code's plugin manifest still lists only the skill. Gemini CLI's extension still names the
  short `ACC.md`. Claude Code's `settings.json` kept its bytes.
- With no Codex service in that home, doctor reported hook readiness as unverified. It started
  no Codex process and left `config.toml` unchanged byte for byte.
- A question recorded under 0.15.4 crossed the update. The peer saw it and replied, the sender
  received the reply, and the store stayed on contract 8.
- All 398 archive files were installed in the active generation with the same SHA-256.
- The update worker ran against the closed port with a due check and named the cause
  `fetch failed (ECONNREFUSED)`. The next due pass against the local registry cleared it.
- The update to 0.15.6 left the hooks plugin on its 0.15.4 copy with the same hash.
- The stable CLI answered 0.15.6 after the npm installation was removed.

The same check ran a second time with the work directory reached through a symbolic link, so
that the data home path goes through a link (#440). All twenty-six checks passed again. The
hook shim kept the data home as configured, through the link, and Codex's hooks plugin kept its
0.15.4 copy and content hash across both updates. Under 0.15.4 this setup moved the hooks plugin
to a new copy, and Codex then asked for the hooks to be trusted again.

## Real clients and other platforms

- #445 and #449 change Windows behaviour only, and #446 changes the Linux diagnostic only. The
  real-clients CI job checks these paths since #251: real Codex, its app-server daemon and ACC's
  live delivery against a local model stub. On Windows the check runs as a standard user. On
  Linux it runs the repair that ACC names for the `0777` daemon executable. The check passed on
  `ubuntu-latest` and `windows-latest` in CI run 45487841789.
- On macOS these changes do not alter behaviour. The upgrade check above covers the archive.

## Full suite

With commit B's evidence in place, the full suite ran 4227 tests under Node 24.4.0 at load average
5–23. Of those, 4214 passed, 13 were skipped and none failed.

## Limits

- The upgrade check opened no Codex, Kimi Code or Gemini CLI session. It proves the files that
  each client reads, not the behaviour of a session that starts after the update.
- Linux and Windows ran in CI only.
